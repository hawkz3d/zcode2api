# 对拍器独立验证（captain，2026-10-15）

> 目的：Liche 是 harness 的作者，他自测通过不能作为唯一信任依据。
> 本文件记录 **captain 独立复跑**的结果，作为「裁判可信」的第二重证据。

## 环境

- systemd 252 / 内核 6.18.18.c952-trim（不相关，仅记录）
- baseline：`http://127.0.0.1:9120`（运行中的老服务）

---

## 测试 1 · 自测（baseline vs baseline，应全绿）

```bash
python3 scripts/conformance/harness.py \
  --baseline=http://127.0.0.1:9120 --candidate=http://127.0.0.1:9120
```

**结果**：**25/25 case 全部 `L1:PASS L2:PASS L3:PASS`**，零假阳性。

意义：证明归一化规则不会把"同一份响应"判成差异 —— 裁判不产生**假阳性**。

---

## 测试 2 · 破坏检测（candidate 指向死端口，应全 FAIL）

```bash
python3 scripts/conformance/harness.py \
  --baseline=http://127.0.0.1:9120 --candidate=http://127.0.0.1:19999
```

**结果**：全部 case `L1:FAIL`，且标注 **「每轮均不一致：重试穷尽，非偶发」**
（说明重试机制正确区分了「偶发」与「稳定失败」）。

意义：证明裁判不会把"完全不同的服务"判成通过 —— 不产生**假阴性**。

---

## 测试 3 · 退出码（自动化判定依赖）

| 场景 | 退出码 | 期望 | 结论 |
|---|---|---|---|
| baseline ≠ candidate（全 FAIL） | **1** | 非 0 | ✅ |
| baseline == candidate（全 PASS） | **0** | 0 | ✅ |

意义：可用于 CI / 脚本门禁（`harness.py ... || echo "对拍未通过"`）。

> ⚠️ 记录一次 captain 自身的误判：初次观察时把 `harness.py | tail` 的**管道退出码**当成了脚本退出码，
> 误以为"失败也返回 0"。直接执行（不经管道）后确认退出码正确。
> 教训与 ADR-005 同源：**观察管道/包装层的结果，不等于观察目标本身**。

---

## 结论

对拍器（Liche 交付，t4）经 captain 独立验证：
- ✅ 无假阳性（同源全绿）
- ✅ 无假阴性（异源全红，且区分偶发/稳定）
- ✅ 退出码可用于自动化门禁
- ✅ 已知差异走显式豁免清单（默认空 = 零容忍）

**裁判可信，可用于 t6 候选验收。**
