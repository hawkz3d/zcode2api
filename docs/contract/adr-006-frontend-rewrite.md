# ADR-006 · 前端处置：重写但保持结构等价（选项 C）

- 状态：**已裁定**（2026-10-15）
- 裁定人：**用户**（项目所有者）
- 触发：captain 发现「对拍要求 HTML 字节等同」与「去除历史来源」目标冲突

## 冲突

| 目标 | 要求 |
|---|---|
| 契约等价（对拍） | 页面 HTML 逐字节相同（`UI-*-page` case 用 L1+L3 字节对拍） |
| 去除历史来源 | 新仓不含他人代码（老仓 `frontend/` 104KB 为他人所写） |

## 裁定：**C · 重写但保持结构等价**

用户拍板。具体含义：

### 允许的差异
- 空白、缩进、换行、注释
- 属性顺序
- 模板实现方式（Go 而非 Jinja2）

### 必须保持等价（不可变）
1. **DOM 结构**：元素层级、标签名
2. **`id`**：全部保持（`accounts.html` 有 **43 个**）——JS 靠它取元素
3. **`class`**：全部保持（`login.html` 10 处 / `accounts.html` 175 处）——CSS 靠它渲染
4. **`data-*` 属性**：保持（`accounts.html` 有 3 处）
5. **静态资源引用**：路径与版本查询串保持（`/static/css/app.css?v=2.5.1` 等）
6. **外部 CDN 引用**：`https://cdn.jsdelivr.net/npm/geist@1.0.0/dist/fonts/geist-sans/style.css` 保持
7. **可见文本**：标题、按钮文案、表头等保持（用户可见，属契约面）

### 判据（可机器验证）
新服务渲染的 HTML 与老服务对比：
- **结构化提取后等同**：解析 DOM → 比对「标签名 + id + class 集合 + data-* + 文本节点」
- 忽略：空白、注释、属性顺序

## 关键简化：模板只有一个变量

captain 实测：老仓 `frontend/admin/*.html` 中**模板变量只有 `{{APP_VERSION}}`**（共 15 处），
**无 `{% if %}` / `{% for %}` 等控制结构**。

值来源：`frontend/version` 文件内容（`2.5.1`）。

**含义**：新服务**不需要实现模板引擎**，只需**字符串替换**（或 Go `text/template` 的极简用法）。
重写成本远低于预期。

## 对拍处置

`UI-login-page`、`UI-monitoring-page` 两条 case 当前期望 **L1+L3（字节）**，
选项 C 下会产生**已知差异**（空白/注释不同）。

**处置**：在对拍豁免清单登记条目（形如）：
| 字段 | 内容 |
|---|---|
| case | `UI-*-page` |
| 差异形态 | 页面 HTML 非字节等同（空白/注释/属性顺序差异） |
| 理由 | ADR-006：重写以去除历史来源，保持 DOM 结构等价 |
| 批准人 | 用户拍板（2026-10-15） |

⚠️ **但豁免不能变成"无所谓"**——需要**替代验证**：
- 新增结构化对比 case（DOM 结构/id/class/文本等同），或
- 人工核对清单（captain 已提取 43 个 id / 175 个 class 作为核对基准）

**转 Liche（t8 或后续）**：把「页面结构等价」做成可机器验证的 case，替代纯字节对拍。

## 不做的事（明确边界）

- ❌ 不照抄老仓 `frontend/` 的任何文件到新仓
- ❌ 不复刻 Jinja2 模板语法
- ❌ 不为了"字节等同"而保留外部资产

## 相关工作

- 静态资源契约补充：`static-assets-spec.md`（页面/资源响应头、ETag/304、对拍缺口）
- 前端规模：9 文件 / 104KB（`accounts.html` 760 行最大）
